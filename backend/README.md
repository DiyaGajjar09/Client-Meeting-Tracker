# Client Meeting-to-Action Tracker — Backend API

Enterprise FastAPI backend foundation for **Client Meeting-to-Action Tracker** powered by **Python 3.11+**, **MySQL 8.0+**, **SQLAlchemy 2.x**, **Alembic**, and **Pydantic v2**.

> [!IMPORTANT]
> **Zero SQLite Policy**: This application strictly uses MySQL 8.0+ for all persistence, migrations, and integration tests. SQLite is not used anywhere in the codebase.

---

## 1. Prerequisites

- **Python**: Version 3.11 or newer (Python 3.11, 3.12, 3.13, 3.14 supported).
- **Database**: MySQL 8.0+ running natively or via Docker.
- **Node.js / npm**: (Optional, for the companion React frontend located in `../client-meeting-action-tracker/`).

---

## 2. Database Setup

### Option A: Using Docker Compose (Recommended)

A ready-to-run [`docker-compose.yml`](docker-compose.yml) and [`init-db.sql`](init-db.sql) are included in this directory.

```bash
cd backend
docker compose up -d
```

This starts a MySQL 8.0 container configured with:
- **Port**: `3306`
- **Charset**: `utf8mb4`
- **Databases created**: `meeting_action_tracker` (production/dev) and `meeting_action_tracker_test` (automated tests)
- **User**: `meeting_app` / Password: `change_this_password`

To stop the database:
```bash
docker compose down
```

### Option B: Local MySQL 8.0+ Server

If you are running MySQL on your local machine or an existing server, create the database and user by executing:

```sql
CREATE DATABASE IF NOT EXISTS meeting_action_tracker CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE DATABASE IF NOT EXISTS meeting_action_tracker_test CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE USER IF NOT EXISTS 'meeting_app'@'%' IDENTIFIED BY 'change_this_password';
GRANT ALL PRIVILEGES ON meeting_action_tracker.* TO 'meeting_app'@'%';
GRANT ALL PRIVILEGES ON meeting_action_tracker_test.* TO 'meeting_app'@'%';
FLUSH PRIVILEGES;
```

## 8. API Endpoints Overview

All routes are mounted at both the root `/` and `/api/v1/`:

| Method | Path | Description |
|---|---|---|
| `GET` | `/health` | Connectivity check (`SELECT 1`), status, version, and MySQL engine info |
| `POST` | `/clients` | Create a new client (name normalized, 409 on duplicate) |
| `GET` | `/clients` | List all registered clients with meeting counts |
| `GET` | `/clients/{client_id}` | Retrieve specific client details (404 if not found) |
| `POST` | `/meetings` | Upload meeting via `multipart/form-data` (`.txt`, `.docx`, `.pdf`, `.vtt`, `.srt`) |
| `POST` | `/meetings/json` | Create meeting via JSON payload (for pasted transcript text) |
| `GET` | `/meetings` | List meetings with pagination (`skip`, `limit`) and client filter |
| `GET` | `/meetings/{meeting_id}` | Retrieve full meeting details including sanitized transcript |

| `POST` | `/meetings/{meeting_id}/extract` | **Execute Gemini AI extraction pipeline with zero-hallucination verification** |
| `GET` | `/meetings/{meeting_id}/items` | List all action items extracted for this meeting |
| `DELETE` | `/meetings/{meeting_id}` | Permanently delete meeting transcript and cascading items |
| `GET` | `/items` | List action items with meeting, type, and review filters |
| `PATCH` | `/items/{item_id}` | Accept, reject, or edit item & record review event |
| `DELETE` | `/items/{item_id}` | Permanently delete item and its audit log |

## 9. Google Gemini AI Extraction Engine

The backend features an AI Meeting Extraction Engine powered by Google Gemini (`google-genai` SDK):

### Features & Zero-Hallucination Guarantees:
1. **Never Invent Owners**: Missing owners strictly default to `name=null` and `state="not_stated"`. Generic terms ("someone", "we", "the team", "TBD") are automatically sanitized to `None`.
2. **Never Invent Deadlines**: Tasks without explicit deadlines receive `resolved_date=null` and `state="not_stated"`. Vague phrases ("asap", "by end of week") are preserved in `raw_wording`.
3. **Deterministic Relative Date Resolver**: Relative dates like "Friday", "tomorrow", or "next Monday" are resolved deterministically against the meeting date. If meeting date is absent, `resolved_date` is strictly left `null`.
4. **Verbatim Evidence Citations**: Every item must cite a verbatim quote with fuzzy-match ratio $\ge 0.85$, line numbers, and speaker attribution. Quotes missing from transcript are downgraded to `LOW` confidence and flagged.
5. **Reversal & Cancellation Detection**: The engine scans for retroactive reversals and cancellations (e.g. "scratch that", "changed our mind") and updates items or flags them for clarification.
6. **Provider-Independent Interface**: Uses abstract `LLMClient` with both `GeminiLLMClient` for live inference and `MockLLMClient` for deterministic unit testing.

### Configuring Gemini:
Set your Google Gemini API key in `backend/.env`:
```dotenv
GEMINI_API_KEY=your_actual_gemini_api_key_here
GEMINI_MODEL=gemini-2.0-flash
```

## 10. Frontend Integration

The companion React frontend is located in `client-meeting-action-tracker/`.

To connect the React app to this FastAPI backend:
1. Ensure the backend is running on `http://127.0.0.1:8000`.
2. In `client-meeting-action-tracker/.env`:
   ```dotenv
   VITE_API_BASE_URL=http://127.0.0.1:8000
   ```
3. Start the React dev server:
   ```bash
   cd client-meeting-action-tracker
   npm run dev
   ```
